# Current limitations

This is a working native instrument build, not a claim of commercially finished acoustic modelling or universal host certification.

1. **Audition remains necessary.** The 114 presets are original, reproducible synthesis recipes. All load and render, but none are claimed to have been approved by ear by Arash. The generated WAV demonstrates six categories.
2. **Anti-aliasing is finite.** Saw/pulse use polyBLEP, triangle uses a limited odd-harmonic series, and the engine/effects run at 2x with filtered downsampling. Extreme hard sync, FM, very high notes and aggressive nonlinear drive can still alias. No claim of alias-free operation or commercial reference-synth equivalence is made.
3. **Filter modelling is approximate.** The ladder uses a closed-form feedback/TPT design with bounded nonlinearities; the other models use TPT state-variable integrators. They are not component-by-component circuit emulations. Resonant/self-oscillating operation is supported, but exact self-oscillation tuning across the keyboard is not calibrated.
4. **Global modulation semantics.** Oscillator, envelope and filter destinations are per voice. Effects, gate, sequencer and master use the most recently started active voice as their modulation source context. Structural controls act at control/note boundaries; use ordinary continuous sound parameters for smooth modulation. The matrix runs at a 32-internal-sample control interval.
5. **Sound-changing switches.** Continuous parameters are smoothed. Changing waveform, filter model, routing or voice mode during a held note can produce a transient. The filter response graph is an illustrative guide, not a measured response analyzer.
6. **UI density.** The 1280 × 720 main face is shared exactly by app and plugin. Detailed parameters are reachable in a searchable secondary window; all 264 controls are not simultaneously drawn on the main face. The smallest supported face is 1000 × 562.
7. **Mac architecture and signing.** Supplied binaries are arm64 and ad-hoc signed. They are not notarized; Intel and Windows binaries are not built here. Windows and universal-Mac build files are included. No AU, AAX, VST2, CLAP or Linux binary is supplied.
8. **Standalone desktop launch.** The app bundle builds and passes code-signature verification, and its shared processor/editor pass integration tests. Launch Services returned `-10827` in this restricted session; directly starting the executable aborted inside macOS `_RegisterApplication` before synth initialization. The desktop automation service also failed to obtain even a Finder window. A normal desktop launch and physical audio/MIDI device test remain unverified.
9. **DAW coverage.** An independent JUCE test host loads the actual VST3 and checks audio, state and editor creation. This does not certify every DAW or a long live performance. Offline CPU figures exclude audio-device scheduling and interface rendering.
10. **Chord and MIDI scope.** Chord memory stores four intervals, within ±24 semitones, and plays them in Poly mode. Per-channel pitch bend/pressure and sustain are supported; polyphonic pressure is treated as channel pressure. This is not an MPE implementation. Hardware MIDI CC learn requires the GUI message loop to deliver its queued parameter changes.
11. **Optional brainstorm items.** The roadmap's post-build brainstorm is not a mandatory feature list. Tape brake, hand-drawn pump curves and a Mint/Used/Beat-up condition switch are not implemented. Age, tolerance, chord memory, mutation, A/B, undo, MIDI learn and scope persistence are implemented.

The native application supersedes the roadmap's browser-specific HTML/CSS/AudioContext interface. It does not contain a browser harness or the other instrument/host mixer.
