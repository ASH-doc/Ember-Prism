# Practical limits and verification gaps

- Included Mac app/VST3: Apple Silicon arm64, macOS 11+ target, ad-hoc signed. No Developer ID signature or notarization. Intel/universal and Windows builds have build files but were not compiled here.
- The actual VST3 passed an independent host test. Native editor snapshots pass at 1000, 1280 and 1600 pixels wide. This does not establish compatibility with every DAW, hardware audio device, display scale or operating system. Standalone desktop/device playback needs a user check.
- High-note base table playback is bandlimited with ten mip levels; the full engine runs at 2x with a 47-tap decimator. Nonlinear sync, FM, PWM, wavefolding and quantization can still create aliasing at extreme settings. No assertion of completely alias-free warping, universal click-free switching or commercial sound-designer approval is made. Table/filter/warp type selectors are discrete; use modest levels when switching them under sustained notes.
- Sixteen notes with two oscillators and moderate unison passed the offline performance check. Maximum 16-unison on both oscillators is expensive; reduce unison/polyphony or raise the buffer on slower machines. Offline wall time is not an audio-dropout guarantee.
- One imported asset is current per patch and may be selected by either oscillator. Importing a new asset replaces that shared imported slot. Each instance retains up to 32 unique imports until it is reopened, to keep pointers safe for the audio thread. Whole-file single-cycle import treats the entire file as exactly one period; use the strip mode for multi-frame tables.
- There are 24 modulation routes. All schema parameters can be targeted, including structural selections; integer parameters are quantized and structural changes occur at control boundaries. Voice parameters use per-voice modulation. Shared effects, master and performance controls use the most recently started active voice's sources. When no voices remain, those sources return to their base values.
- Continuous base parameters slew over approximately 12 ms at the control rate; control refresh is every 32 internal samples. Modulation can intentionally be stepped. Host automation is sampled at block boundaries; MIDI notes retain sample offsets. MIDI CC learn uses a message-thread update and is not sample-accurate. Polyphonic key pressure currently feeds the channel pressure source.
- Host tempo/PPQ sync is supported while transport plays. It does not implement a DAW song-position clip sequencer, MPE expression, MIDI output or audio input. Arp and sequencer generate their own notes from held/latching keys. Panic clears voices, held notes and effects.
- FX have eight common schema controls: on, mix, A/B/C, mode, sync and division. The visible A/B/C labels depend on the module. For reverb, distortion, EQ, compressor, filter and widener, Sync is named Tempo motion and rhythmically modulates the wet contribution. The reverb is a compact algorithmic FDN with octave feedback, not convolution.
- Duplicate manually automated rack slot selections resolve deterministically to unused modules, so each module runs once. The UI and exported descriptive rack use the same resolution. Drag reordering writes a unique order directly.
- Optional PDF brainstorm features—light theme, spectral wavetable editor and continuous scene morphing—are not implemented. Drawable LFOs, WAV import, randomizer and snapshot/swap are implemented. The PDF's JavaScript global/AudioContext contract is replaced by the native C++/JUCE contract, as requested.
- Presets are generated original recipes with validation and audio renders. They still need musical listening and level matching in your own sessions; they have not had a human sound-design listening pass.
