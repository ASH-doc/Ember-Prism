# Spire 1.5 calibration findings (first session, 2026-11-03)

Obtained by driving Spire inside FL Studio (computer use, Arash's machine) and reading the saved `.spf2` files. Only facts about the file format and Spire's own lists are recorded here. No third-party preset content. The calibration files themselves stay on Arash's machine (`%APPDATA%\RevealSound\Banks\AEther calibration`).

## How the fixtures are made
Spire's own library browser has a Save button. It writes a plain-text `.spf2` straight into `%APPDATA%\RevealSound\Banks\<folder>`, so each fixture can be read the moment it is saved. The INIT button loads Spire's initial patch. (If a typed file name has no `.spf2` the file is saved without an extension; type it.)

## Established
- **`*_mute` flags**: 1 = muted. Saved fixture S02 has all five effect MUTE buttons lit red and `chr_mute`, `del_mute`, `phs_mute`, `rev_mute`, `shp_mute` all changed 0 to 1 against the initial patch S01. The earlier library statistics therefore mean that 93 to 97% of presets leave each effect not muted; they say nothing about the wet level.
- **`eq_power`**: 1 = EQ on (switching the EQ on changed 0 to 1).
- **Initial patch (S01)**, the baseline for "fields that differ from default": 722 fields; oscillator 1 type Classic, wave Sin, mix 0.5, the other three oscillator mixes 0; no oscillator muted; filter 1 type `perfecto` mode LP4 cutoff 1.0 resonance 0; filter 2 off; effects not muted, all wet values 0; EQ off.
- **List choices are stored as index / 999 with index 0 first.** Confirmed against the screen: filter 1 type `perfecto` is list item 1 and stored as 0.001001; `Classic` and `Sin` are item 0 and stored as 0.
- **Spire's own displays are not in real units.** The manual says knobs run from 0 to 1000 (centre 500); the LCD shows such numbers. Hz, seconds and cents for cutoff, envelopes and so on are *not* available from Spire's display. They have to be calibrated from audio (render, measure) against the evaluation score, as was done for the Claude import. The planned "36 numbers" step of the recipe is dropped.

## Audio calibration, first run (2026-11-03)
**Pipeline that works end to end:** I write test presets myself by editing the initial patch (S01) and saving them in the calibration folder; Spire re-indexes its whole library after Rescan (about 8 minutes with 72,000 presets, FL Studio used up to 9.4 GB meanwhile, so rescan as rarely as possible and write all test presets first); I load each one from Spire's list, FL Studio renders a 16-step pattern to a 32-bit float WAV (File, Export, Wave file), and `DualFilterProbe` measures the spectrum. Nine renders (cutoff stored value 0.1 to 0.9, noise oscillator, filter 1 Perfecto LP4, no resonance, no effects) were made.

**First result: inconclusive, not a calibration.**
- Spire's noise oscillator is not white: its spectrum falls steeply above about 300 Hz on its own, so the corner measured on the noise alone (about 250 to 297 Hz) says nothing about the filter.
- Relative to the 0.9 render, the 0.1 render is about 3 dB quieter even at 60 to 150 Hz, and the renders for 0.3 and above differ by less than 1 dB there, so the 0.9 render is itself not "open". The filter's real corner for the high settings lies above what this source can show.
- The slope measured above the noise corner is 21 to 24 dB per octave, consistent with a four-pole low-pass for the Perfecto LP4 mode (a weak hint only).
**Next design:** use a source with a flat or known spectrum (a sawtooth wave at a low pitch and read the harmonic peaks), render a cutoff of exactly 1.0 as the open reference, use more stored values below 0.5, and measure each render relative to the open one. Envelope times need a long held note (piano-roll note), not 1/16 steps.
## Audio calibration, second run (2026-11-03)
- **Spire reads a preset file when you load it.** I overwrote the content of existing, already indexed test presets and Spire played the new content without another Rescan (the cutoff 1.0 render differed from the earlier 0.1 render of the same preset name). Only a *new file name* needs a Rescan (about 8 minutes). So all later test presets reuse existing file names.
- **Cutoff stored values 0.8, 0.9 and 1.0 render identically**: the filter is fully open from 0.8 up (with the fixed settings of this test).
- **`osc1_mixto` = 1 bypasses filter 1 completely** (render equals the open one within 0.2 dB); 0 sends the oscillator through it. `flt_balance` had no effect on this signal (0 and 1 gave the same render).
- **The cutoff response measured so far is not a simple low-pass.** Relative to the open render, cutoff 0.1 shows about -3 dB at 70 Hz, a dip of about -10 dB near 400 to 700 Hz and about -4.5 dB above 1 kHz; 0.2 about -2 dB, -7 dB and -2.7 dB; 0.3 about -1 dB, -3 dB and -0.4 dB; 0.4 and above under 1 dB. That shape (a mid dip with a shallow floor) looks like a filtered path mixed with an unfiltered one rather than a steep low-pass, and it is not explained yet. No Hz-per-value curve can be claimed.
- **Conclusion for the contract:** explicit unit curves from this kind of renders need a cleaner test design (known source spectrum, resonance and routing fixed, check of the filter's own gain) and are slow. The fallback that does not need them is the one used for the Claude import: convert the stored value with a plausible curve, then **calibrate per preset by objective score** against the Spire render of that preset (which the contract's fidelity measurement requires anyway).
## Score-based correction instead of unit curves (2026-11-07)
Decision (Arash, after the second calibration run): do not derive Hz and second curves from test renders; translate with plausible default curves, then correct loudness, filter cutoff and envelope times per preset against a render of the original Spire preset, using the agreed score.
- `Source/Import/SpireToEmber.*`: translator v0. Oscillators 1 to 3 (waves, levels, octave, tune, unison), filters 1 and 2 (type, mode, cutoff, resonance), envelopes, effects (chorus, delay, reverb, phaser, shaper), arpeggiator, the modulation matrix and the direct envelope and LFO targets, with a report row for every active setting (Mapped, Approximated or Omitted with a reason). Oscillator 4, the combo and shaper filters, the master EQ and compressor, a second modulation source and the arpeggiator step pattern are Omitted rows. A preset whose first three oscillators are silent is Blocked.
- `Tools/SpireImport` (`DualSpireImport`): `translate` writes the EMBER patch, the report and an EMBER render; `batch` compares each translated preset with a WAV render of the original and searches loudness, filter cutoff shift (up to two octaves) and envelope time scale (up to three octaves) for the lowest score.
- Tuning and evaluation sets drawn with `DualSurvey spire-select` (seed 20261107, 1,079 factory presets, stratified: 5 basses, 5 leads, 4 plucks, 2 pads or keys, 4 hard cases; the two sets share no preset). The lists and the copied files stay on Arash's machine.
- First translation run: all 40 selected presets translate and EMBER accepts every patch and renders sound (no silent result). Every one of them is an **Approximation**; none is Opened, none Blocked. Mapped / Approximated / Omitted rows per preset range from 0-1 / 10-28 / 1-24. There is no fidelity result yet: the Spire reference renders have not been made.
- Obstacles met: a full library Rescan took more than 15 minutes the second time and then FL Studio crashed inside Spire.vst3 (access violation, offset 0x19e090), leaving a second FL process running and the Spire window unresponsive to clicks. Plan: do not rescan again. The 14 preset names Spire already indexes (C01 to C09, S01 to S05) are reused as slots: overwrite a slot's file with the preset to render, load the slot, render, and name the output after the preset.
## Saving behaviour to remember
Spire writes edits into the currently loaded library preset when another preset action happens (S02 was overwritten by the later slot-source edits; its original mute/EQ state is also contained in it). Use Create with a new name to freeze each state, and read the file right after.
