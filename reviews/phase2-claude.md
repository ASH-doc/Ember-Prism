# Phase 2 — host controls and master DSP (Claude)

Branch `integration/dual-synth`. Arash asked Claude to do the whole of Phase 2, including the panel layout, and asked for the master compressor to be modelled on a "76" FET compressor with an old-school gain-reduction display. Claude read "76" as the classic 1176-style FET limiting amplifier (4 / 8 / 12 / 20 ratio buttons, all-buttons-in mode, needle gain-reduction meter). If Arash meant a different unit, only the `FetCompressor` class and the meter need to change.
Environment of every result: Windows 11, MSVC 19.44, JUCE 8.0.9 vendored, Release x64. **macOS, DAW, listening: not run.** All sound parameters below were tuned by measurement only, never by ear.

## What was added
| Contract item | What it is | Where |
|---|---|---|
| Pan | `a.pan`, `b.pan` (-1..1). Balance law: centre is exactly unity, so a centred strip is bit-identical to before. | `Host.cpp` `panGain` |
| Solo | `a.solo`, `b.solo`. A strip is audible if not muted and (nobody soloed or it is soloed). Both engines keep running. | `stripGain` |
| Stereo meters | A, B and output, left/right bars on the panel, from `DualProcessor::levels[6]`. | `Host.cpp`, `EditorWidgets.h` `LevelBars` |
| Split swap | `swap`: A plays the high keys and B the low keys in Split mode. | `routeMidi` |
| Tap tempo | `TAP` button (UI gesture) + `tap.target` (both / A / B). Averages up to 8 taps, restarts after 2 s, clamps 30..300 BPM, writes each chosen engine's `clock.bpm` and turns its `clock.host` (follow host) off. | `DualProcessor::tapTempo` |
| Master compressor | New type **FET 76** next to the baseline **Glue** compressor (`comp.mode`). New instances default to FET 76 at 12:1. Baseline recalls get Glue (see "Old saves"). Controls: `fet.input` 0..40 dB, `fet.output` -24..12 dB, `fet.attack` 20..800 us, `fet.release` 50..1100 ms, `fet.ratio` 4 / 8 / 12 / 20 / ALL, `fet.mix` (parallel), `fet.hpf` (fixed 90 Hz detector filter, on by default). | `Source/MasterDsp.h` `FetCompressor` |
| Gain reduction display | Cream backlit analog needle meter, 0 dB at right, red zone from 10 dB, VU-style ballistics; works for both compressor types. Also a numeric "GR" readout bottom right. | `EditorWidgets.h` `GainReductionMeter` |
| Reverb extras | `verb.predelay` 0..100 ms, `verb.lowcut` 20..600 Hz on the reverb send. Neutral at their defaults (bit-transparent). | `MasterDsp.h` `ReverbInputStage` |
| UI | Right strip re-laid out inside the existing routing / mixer / master sections: routing + split + swap + tap; note ranges; mixer with gain, pan, mute, solo and level bars per strip; master with Master FX switch and three tabs (COMP, REVERB, TONE), output meter at the bottom. Custom knob look for the host strip. | `Editor.cpp`, `EditorWidgets.h` |

How the FET 76 works (an approximation of the style, not a circuit model): input gain drives the signal into a fixed -10 dB threshold; hard-ish knee (2 dB); ratio buttons give 4, 8, 12 and 20:1; ALL adds a 28:1 ratio, a threshold 3 dB lower, 2x faster attack and 1.7x faster release; gain reduction is smoothed in dB with the attack and release times; a tanh "grit" is blended in proportionally to the gain reduction (exactly zero grit at zero gain reduction); optional 90 Hz sidechain high-pass; output trim; parallel mix. No look-ahead, zero latency (host latency stays 16 samples).

## Deviations from contract item 6 (for GPT and Arash to accept or reject)
1. **Compressor type.** Item 6 asked for knee / makeup / parallel mix / fixed 90 Hz high-pass in an "extended compressor path". Arash asked for a 76-style compressor instead, so the extended path is the FET 76: makeup = output control, parallel = mix, 90 Hz filter = `fet.hpf` (a switch, default on, instead of fixed). There is no separate knee control (FET 76 has a fixed 2 dB knee; ALL has none).
2. **Reverb decay not added.** The master reverb is the baseline Freeverb: its Size control already sets the decay length and it has no independent decay time, so a separate Decay control would duplicate Size. Pre-delay and low cut were added.
3. **New default.** `comp.mode` defaults to FET 76 (Glue stays available). Master FX is still OFF by default.

## Compatibility
- **IDs.** 16 new IDs only, appended: `a.pan b.pan a.solo b.solo swap tap.target comp.mode fet.input fet.output fet.attack fet.release fet.ratio fet.mix fet.hpf verb.predelay verb.lowcut`. The 810 baseline parameters (host and bridged `A.` / `B.`) are checked against `Tests/baseline-parameter-catalog.txt`, generated by the same function from the unmodified baseline build: id, name, steps, discrete, boolean, default, range endpoints and every choice text. Result: missing 0, changed 0, added 16.
- **Old saves.** A performance saved by the baseline contains none of the new controls. `loadPerformance` gives each new control its neutral value and `comp.mode` = Glue, so old recalls sound as before and do not inherit leftovers from the running instance. Tested with a state whose new controls were removed.
- **Legacy sound.** `Tests/golden-master-fx.bin` is a 160-block render of the whole plugin with Master FX, compressor, reverb and EQ on, rendered by the host BEFORE Phase 2 (commit 240f29e). With `comp.mode` = Glue and default new controls, the Phase 2 host reproduces it with largest sample difference exactly 0 on this machine. The test tolerance is 1e-4 (-80 dB) only to absorb compiler/CPU float differences on other platforms.

## Not done / open
1. **Nothing has been listened to.** The FET 76 defaults (input 6 dB, output 0 dB, 12:1, 100 us / 250 ms) are a measured starting point, not a tuned sound. Arash should audition it on real material; the grit amount and the ALL-mode behaviour are the most subjective parts.
2. Pre-delay and low-cut changes are not smoothed (an abrupt change can click). The pre-delay control is 0 by default.
3. The UI was checked in rendered screenshots only. Mouse interaction (ratio buttons, tabs, TAP) was not driven by hand; parameter attachments are tested through the processor.
4. Meter ballistics and the needle were judged by eye on static renders, not in motion.
5. macOS: not run. GPT to verify this commit on Mac (new tests use real time sleeps for tap tempo, about 1.5 s).
6. `chatgpt/EmberVA`, `chatgpt/PrismFlux` untouched. `docs/ENGINE-INTEGRITY.json` still needs GPT's update for the Phase 1 engine edits; Phase 2 changed no engine file.
7. `README.md` of the project still describes the baseline master section; it has not been updated for the new controls.
