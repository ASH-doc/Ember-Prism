# PRISM Signal & Motion

Open index.html in a browser. Drag either wavetable display to scan position. Switch Filter 1 and Filter 2 and drag the graph horizontally for cutoff or vertically for resonance. Raise Motion Amount and start Preview motion to see the three editable loops interact. The browser uses synthetic waveforms, illustrative responses, and mock state.

## Native layout

- Keep the graphite host sidebar, EMBER surface, PRISM preset browser, macros, and MIDI keyboard. Inside PRISM, use two equal oscillator cards above a wide filter card. Reserve around 140–160 logical pixels for each waveform and 160–180 for the filter graph at the design size. Keep secondary controls reachable through the existing Edit panels. On compact hosts, use a scoped viewport or a Signal view within PRISM so controls retain usable sizes.
- In `Engines/B/Source/sb-ui.cpp`, enlarge `WaveView` for each oscillator. Draw the actual selected table using the same source selection as the oscillator, including factory, imported WAV, and Claude tables. Bind drag and keyboard alternative to `osc1.pos` and `osc2.pos`. Keep table, level, unison, both warp controls, WAV import, and the oscillator inspector reachable. Label the graph as a wavetable preview, distinct from a post-warp audio scope.
- Use one enlarged `FilterView` with Filter 1 and 2 selectors that only change which filter is edited. Bind X logarithmically to 20 Hz–20 kHz and Y to resonance. Retain `fltN.on`, `type`, `cutoff`, `res`, drive, mix and the other inspector controls, plus `filter.route` and balance. Offer cutoff and resonance controls for keyboard access. Use one gesture for a graph drag with matching begin/end for each touched parameter. Show bypass distinctly. Use an illustrative response for nonlinear and time-varying modes and label it as an estimate. Keep graph generation off the audio callback.

## Motion architecture proposal

- Place an automatable **Motion Amount** rotary in PRISM next to the Motion editor. It scales the combined effect of the enabled motion lanes from 0% to 100%. Zero is the compatibility default. Existing arp, note sequencer, drawable LFOs, Euphoria and Space keep their own behavior. The preview transport exists only in the prototype.
- Start with three bipolar lanes, each with up to 16 values, independent loop bounds and tempo division, and Step or Glide interpolation. Suggested initial destinations are OSC 1 Position, OSC 2 Position, and Filter 1 Cutoff. Use host beat when available and the existing PRISM clock otherwise. Use a shared per-instance beat anchor, with transport jumps resolved deterministically. Lanes generate modulation values rather than MIDI notes.
- Use a fixed-size sequence configuration. Validate and publish edits from the message thread to audio at the block boundary through the established bounded handoff. Compute lane values at the existing modulation rate and apply destination offsets after base parameter reads using each destination's normal scaling and clamping. Smooth amount changes. Preserve preset base values. When amount is zero, skip the new path to preserve legacy renders.
- Before implementation, audit schema capacity, modulation destination ordering, and host parameter maps. An appended Motion Amount parameter and a versioned optional PRISM motion payload are proposed. Preserve existing IDs and indices. Missing payloads load disabled. No new IDs or state fields are introduced by this design branch. Publish read-only step indices for UI highlights and use bounded work with no allocations on the audio thread.
- Windows acceptance in FL Studio covers graph dragging and keyboard controls, both filter banks, factory/imported wavetable rendering, host automation, old preset recall, motion save/reopen, tempo and transport changes, and differently sized loops. With Motion Amount at zero, compare against a pre-change render. Check that switching engines leaves the graphite sidebar and EMBER controls intact.

Design references are [Xfer's Serum oscillator and filter documentation](https://xferrecords.com/web-manual/serum-2/using-oscillators-and-filters) and [Korg's modwave lane overview](https://www.korg.com/us/products/synthesizers/modwave_mk2/index.php).
